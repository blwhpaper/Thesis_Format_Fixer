规则与帮助

使用说明与能力边界

这里不发明新语义，只解释仓内现有 API 和报告字段，帮助普通用户理解“检查 / 修复 / 人工复核”分别代表什么。

模式差异

真实后端语义
  • `check`：生成技术报告与用户摘要，不生成修订稿下载。
  • `fix`：会生成 `*.fixed.docx`，但当前仍受 V1 安全边界约束，不能描述成“全自动彻底修复”。
  • 结果页必须同时展示“未自动修改”和“需人工复核”，避免误解成完全无人工参与。

结果三层结构

页面展示约定
  • 第一层：用户友好摘要，优先展示 `user_summary.overall_status`、`key_issues`、`next_steps`。
  • 第二层：问题明细表，基于 `categorized` 三类结构化列表展开。
  • 第三层：技术报告，直接展示原始 payload/JSON，不另造第二套报告结构。

下载项说明

只认 API 真值
  • 报告下载：仅当 `artifacts.download_report_md_url` 存在时展示按钮。
  • 修订稿下载：仅当 `artifacts.download_fixed_docx_url` 存在时展示按钮。
  • 若 fix 结果中没有修订稿下载地址，则页面明确提示“当前无可下载修订稿”。

常见失败原因

错误提示入口
  • 未选择文件。
  • 上传的不是 `.docx`。
  • 文件为空或结构异常。
  • API 未启动，或 Base URL 指向错误。
