# IMPLEMENTATION_SCOPE_TASK-003

## 1. 目标与边界

- 本文档定义 TASK-004 可直接开工的最小实现基线。
- 唯一规则基线：`rules/FORMAT_RULEBOOK_v2.md`。
- 本轮不写业务实现代码，只冻结实现切分与模块边界。
- 严格执行：B/C 不进入自动修复；封皮重建、页码分节联动、自动目录重建、脚注按页重编、参考文献内容级纠错不进入 V1 自动修复。

## 2. V1 最小可交付能力（收紧后）

### 2.1 Auto Fix（仅低风险、可稳定定位）

- 摘要区：
  - 中文摘要标题文本与样式（FR-4.2-01/02）
  - 中文摘要正文样式（FR-4.2-03）
  - 中文关键词样式（FR-4.3-01）
  - 英文摘要标题文本与样式（FR-4.4-01/02）
  - 英文摘要正文样式（FR-4.4-03）

- 独立标题区：
  - 目录标题 `CONTENTS` 样式（FR-4.6-01）
  - 参考文献标题 `REFERENCES` 样式（FR-4.11-01）
  - 致谢标题与正文样式（FR-4.12-01/02）

### 2.2 Auto Check（可稳定检测，不直改）

- 封皮字段存在性（FR-4.1-01/03）
- 关键词分隔与计数规范（FR-4.3-02/03, FR-4.5-03/04/05）

- 页面设置检查：A4、双面语义、不对称页边距、奇偶页不同、页码格式（FR-4.13-01/03, FR-4.14-03, FR-4.15-03）

### 2.3 Report Only（检测可做但 V1 不自动修复）

- 目录内容样式、目录点线、目录-正文一致性（FR-4.6-02/05/06）
- 主标题/副标题、各级标题样式、正文普通段落样式（FR-4.7-01/02, FR-4.8-03/04/05, FR-4.9-01）

- 英文封皮存在+A4、装订顺序、装订线左侧（FR-4.1-02, FR-4.16-01/02）

### 2.4 Out of V1（不实现）

- 页码分节联动重构（FR-4.15-04）
- 装订线版面重排（FR-4.16-03）

## 3. 第一版最小模块边界

> 模块以“先检测、后可选修复、统一报告”组织，避免跨模块隐式写回。

### 3.1 `document_loader`

- 职责：加载 docx，构建只读文档上下文（段落、run、section、header/footer、footnote 引用索引）。
- 输入：文件路径。
- 输出：`DocumentContext`。
- 约束：不做规则判断、不做写回。

### 3.2 `block_locator`

- 职责：基于锚点定位区块（中文摘要、英文摘要、目录、正文、参考文献、致谢、封皮候选）。
- 输入：`DocumentContext`。
- 输出：`BlockMap`（每个块的段落范围+置信度）。
- 约束：低置信度仅供检查，不触发自动修复。

### 3.3 `style_normalizer`

- 职责：对允许 Auto Fix 的低风险块执行样式归一化。
- 输入：`DocumentContext` + `BlockMap` + `FixPlan`。
- 输出：变更集 `StylePatchSet`（可回滚）。
- 约束：仅允许操作白名单规则（本文件 2.1）。

### 3.4 `section_page_setup_checker`

- 职责：读取并检查页面尺寸、边距、奇偶页、页码格式等 section 级规则。
- 输入：`DocumentContext`。
- 输出：检查结果 `CheckFindings`。
- 约束：V1 不执行分节重构、不写回高风险 section 属性。

### 3.5 `footnote_checker`

- 职责：检查脚注/尾注类型与脚注样式合规性（样式仅报告）。
- 输入：`DocumentContext`。
- 输出：`CheckFindings`。
- 约束：不做按页重编、不改编号系统。

### 3.6 `bibliography_checker`

- 职责：检查参考文献标题、条目基础结构、分组/年份/顺序（后两者仅报告）。
- 输入：`DocumentContext` + `BlockMap`。
- 输出：`CheckFindings`。
- 约束：不做内容级改写与重排。

### 3.7 `report_builder`

- 职责：统一输出 `Auto Fix / Auto Check / Report Only / Out of V1` 结果。
- 输入：`StylePatchSet` + `CheckFindings` + 跳过原因。
- 输出：结构化报告（建议 JSON + 人类可读 Markdown）。
- 约束：必须显式标注每条规则的执行决策与证据。

## 4. 规则执行门禁（TASK-004 必须落地）

- 门禁 1：若规则不在 Auto Fix 白名单，一律不可调用写回。
- 门禁 2：`block_locator` 置信度低于阈值（建议 `<0.85`）时，降级为 Report Only。
- 门禁 3：涉及 section 重构、TOC 域重建、脚注重编号的路径必须硬拦截并记录 `Out of V1`。
- 门禁 4：任何 B/C 类规则输出中必须标注 `checked_only=true`。

## 5. TASK-004 直接开工清单

1. 建立规则注册表 `rule_id -> detector/fixer/reporter`（以 `RULE_TO_ENGINE_MAPPING_TASK-003.md` 为唯一映射源）。

3. 实现 Auto Fix 白名单中的摘要/关键词/标题样式归一化。
4. 实现 Auto Check 白名单中的关键词、目录域存在性、标题序号、脚注类型、页面基础设置检查。
5. 报告层输出四类决策分栏，并附 `rule_id`、证据位置、是否可自动修复。
6. 增加回归样例：每条 Auto Fix/Auto Check 至少一个正例和一个反例。
