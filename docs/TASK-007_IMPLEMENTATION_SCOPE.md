# TASK-007_IMPLEMENTATION_SCOPE

## 1. 目标

- 在 V1 安全格式修复链路上新增 V2 审查能力。
- V2 仅做结构化审查与报告，不执行自动修复写回。
- 本地模型仅作为辅助判断器，失败时可降级，不阻断主链路。

## 2. 本轮覆盖范围（B 类最小闭环）

- 标题层级审查（`FR-4.8-01`）：
  - `1` / `1.1` / `1.1.1` 形态识别
  - 层级跳变与疑似混乱
  - 无法稳定识别时输出 `unable_to_judge`
- 参考文献结构审查（`FR-4.11-03`, `FR-4.11-04`）：
  - 是否存在 `[1] [2]` 等编号
  - 英文在前/中文在后顺序疑点
  - 英文文献数量是否少于 5
  - 基础结构是否明显异常（仅疑点提示）
- 页码/正文起始审查（`FR-4.15-01`, `FR-4.15-03`）：
  - 是否疑似从正文开始标页码
  - 页码样式是否疑似 `-1-`
  - 分节/正文起始证据不足时输出 `unable_to_judge`

## 3. 明确保持 Out of Scope

- 不新增任何高风险自动修复能力。
- 不做全文智能改写。
- 不做封皮重建。
- 不做脚注重编号。
- 不做参考文献内容自动纠错与自动重排。
- 不做页码系统重构、分节重构。

## 4. 与现有链路的关系

- 复用既有 `runner`、`document_loader`、`block_locator`、`rule registry`、`report builder`、`CLI`。
- 不新增第二套主处理链路。
- V2 审查结果并入既有报告 JSON/Markdown 的新增区块。

## 5. 执行门禁

- 所有审查 finding 必须输出结构化字段。
- `auto_fix_allowed` 固定为 `false`。
- 模型输出不可直接拼贴为最终报告正文。
- 模型异常/缺失/非法输出时降级为纯规则审查。
