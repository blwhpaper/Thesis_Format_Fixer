1. 学校原始规范来源（含本轮新增policy document文件）
2. 项目补充决议（用于处理来源缺口、冲突或工程可执行性收口）
3. 冻结版规则手册（`rules/FORMAT_RULEBOOK_v3.md`）
4. 后续实现与映射文档（`docs/RULE_TO_ENGINE_MAPPING_TASK-003.md` 等）

执行说明：
- 该顺序与 `rules/FORMAT_RULEBOOK_v3.md` 的证据优先级条款保持一致。
- 若学校来源可读性受限（本轮新增 PDF 为扫描流，无法稳定抽取正文），则先保留来源事实，再通过项目补充决议给出可执行口径。

## 2. 两条新增规则的最终工程口径

### 2.1 英文不能有书名号《》

- 规则编号：FR-4.5-06
- 适用范围：英文正文、英文摘要、英文关键词、英文目录、英文参考文献
- 触发条件：出现中文书名号《》字符
- 执行动作：仅报异常，不自动替换
- 分类：B（自动检查，不直接修改）

### 2.2 D 类参考文献不能有页码

- 规则编号：FR-4.11-07
- 适用范围：`[D]`、`[D/OL]` 等 D 类条目
- 触发条件：条目尾部出现页码或页码区间
- 执行动作：仅报异常，不自动删除页码
- 分类：B（自动检查，不直接修改）

## 3. 为什么本轮只进规则层，不进实现层

基于已读取文件：
- `docs/IMPLEMENTATION_SCOPE_TASK-003.md`
- `docs/V1_OUT_OF_SCOPE_TASK-003.md`
- `docs/RULE_TO_ENGINE_MAPPING_TASK-003.md`

决策理由：
- 本轮任务边界明确要求仅规则层与文档层，不触及 checker/fixer/runner/cli。
- 现有 V1 边界持续强调高风险与语义相关项应先检查后处理，避免误改。
- 两条新增规则都跨区块且涉及语义上下文识别（英文域判定、D 类结构判定），先冻结为 B 类更符合最小风险原则。
